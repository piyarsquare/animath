# Split Decision — the app, then five rounds of use-driven fixes and two new axes

## Summary

A new app at `#/split-decision` (gallery **Storeroom**): a genetic algorithm evolves a
two-way split of a binary matrix under a selectable **judge**, and the experiment is the
**reproductive rule**. Built from a plan + three-hats review, then reshaped across five
rounds of Dan actually using it — a perf fix, a crash he hit on a phone, a correlation
view that could not be read, and two new axes he asked for (sexed payoffs, a relaxable sex
quota). PR [#255](https://github.com/piyarsquare/animath/pull/255) is open with all checks
green at `209084d`; **not merged**.

## What changed

Beyond the app itself (engine, Watch mode's four views, the Lab's worker-pool sweep —
see the progress report), this session's later half was driven entirely by use:

- **Perf.** Watch mode crawled at raised parameters. Profiled rather than guessed: 44% in
  React's reconciler against ~8% in the app's math. Fixed with three cadences
  (generations free, React ≤20 Hz, population stats ≤4 Hz) and canvas for two views.
  24×24/N=256 went 9.2 → 20.1 gen/s.
- **A phone crash Dan hit that nothing here could reproduce.** `TypeError: (intermediate
  value)… is not iterable`, mapped via newly-enabled preview source maps to `Arena.tsx:93`:
  the Arena walks `i < m` over a population snapshot still sized to the *old* matrix for
  one paint after a size change. Fixed by gating a stale snapshot at the source.
- **Two CI holes that let it through.** `RouteBoundary` *catches* the error, so no
  `pageerror` ever fired and a crashed route read as a clean load — the smoke gate was
  blind to **every** contained route crash. It now renders a `data-am-route-error` marker
  the gate fails on, and runs a **poke pass** (open each panel, move every control,
  re-check). `#/split-decision` and `#/counting-the-ways` weren't in the route table at all.
- **The correlation view made block-first.** It read as speckle while the Arena beside it
  read as blocks. Two drawing faults: `r` mapped over the full [−1,+1] put real structure
  (~0.2) off the pale center while the diagonal took the only saturated color, and only
  one boundary was ruled, in a 0.13-alpha hairline. Now ±0.5 fixed scale, block washes,
  every boundary ruled. A **Locus order** pill (Live · Planted · Stored) answers Dan's
  "maybe the positions don't change and something else does".
- **Sexed yields** (new Payoff axis): each gender scored by its own cross block. Under
  **count** the optimum is a cut that doesn't split at all (clonal → conquest 100/0, pot
  captured; Prom → mutual ruin, pot empty). Under **density** (default) the runaway is
  gone and the regime is set by signal: clean checkerboard → both genders and the pot peak
  together at the true split (captured **1.00**); noisy → they hoard one row/column each
  (captured **0.29**).
- **A relaxable sex quota.** `sexQuota` no longer clamps, the ratio runs 0–1, and a
  Drifting mode draws each birth. A generation with one sex present reproduces
  **parthenogenetically** — one parent, both halves, both mutated.

  CLAUDE.md, keeping every app's entries in the append-only shared files.

  good, and is the same machinery a mother's-curse readout needs.

  pre-existing on an unmodified script; not this branch's. Queued as a separate task.

  its panel, but the sweep's default μ = 0.1 makes it report 0/12 for every rule.

## Context

> [!IMPORTANT]
> The Linkage view's ±0.5 color scale is a **constant, not an auto-fit**. Normalizing per
> frame would make the Mixer's noise as loud as the Monastery's signal and destroy the
> exact comparison the view exists for. Don't "improve" it into an auto-scale.

> [!CAUTION]
> `sexedYield` deliberately has **no degenerate guard**, unlike every judge. Under count
> mode the optimum genuinely is a cut that doesn't split; zeroing it would leave the
> dynamic nowhere to go. If you add a guard there you delete the experiment.

> [!NOTE]
> The smoke gate is `continue-on-error`, so it reports without blocking. It currently ends
> `FAIL 18/19` for the pre-existing trees-and-nets route — that is expected, not a

## Self-reflection

1. **What would you do with another session?** Put the app on a real phone. Then the
   heritable sex ratio, which is the change that turns parthenogenesis from a
   per-generation fluctuation into something a lineage can actually commit to — and which
   the mother's-curse readout also needs.
2. **What would you change about what you produced?** The Payoff axis grew two pills
   (Payoff, then Yield) where one three-way control would read better; I chose two to
   avoid migrating a persisted value, which was the cautious call rather than the clean
   one. And `SplitDecision.tsx` is now ~600 lines with eight panel bodies inline — the
   panels want extracting before the next feature lands in it.
3. **What were you not asked that you think is important?** Whether Split Decision should
   leave the Storeroom. It is now considerably more finished than "an experiment that
   isn't ready", and nobody will find it where it sits.
4. **What did we both overlook?** That a route error boundary makes crashes *invisible to
   CI* — we had a headless mobile smoke check built precisely for runtime crashes, and it
   had never been able to see one. That hole predates this branch and affected every app.
5. **What did you find difficult?** The unreproducible phone crash. I spent a long stretch
   reasoning from the V8 message shape and reached a confident, wrong conclusion (that the
   braces of an object literal must be present) because I generalized from Node's V8 to
   Chrome 153's. The frame settled it in one step. I should have built the diagnostic
   path earlier instead of theorizing.
6. **What would have made this task easier?** Source maps on preview deploys from the
   start, and an error panel that carried its own stack. Both exist now.
7. **How did you verify this, and does each passing check test the user-visible claim?**
   Automated tests (369) for every engine claim, and they do test the real quantities —
   the yields, the block sums, the parthenogenesis path, the correlations against an
   independent Pearson implementation. Everything *visual* was headless puppeteer against
   the built bundle: the layouts, the Linkage rendering, the perf numbers, the phone
   widths. **No real device.** The perf figures are gen/s measured in headless Chromium on
   a server, which is a proxy for what a phone feels like, not the thing itself — and the
   crash Dan hit proves headless sweeps here miss what real use finds. `signals:
   phone-needed, visual-unverified` are set for exactly this.
8. **Follow-up value:** MEDIUM — the code is correct and tested and the PR is green, but
   nothing has been seen on a real device, and that is precisely where this session's one
   field-reported bug came from.
